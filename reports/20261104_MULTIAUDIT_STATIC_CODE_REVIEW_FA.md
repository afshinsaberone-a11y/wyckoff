## 1. هدف و دامنه

سورس MultiAudit v1.084 به‌صورت مستقیم و خط‌به‌خط با سورس H1STRUCT Audit v1.083 مقایسه شد تا بررسی شود افزوده‌های تشخیصی Lookback/Pivot، منطق معاملاتی C2 را تغییر داده‌اند یا خیر.

فایل‌های مقایسه‌شده:
- مبنا: `src/Wyckoff_XAUUSD_W0_v1_08_C2_H1STRUCT_AUDIT.mq5`
  - Git blob SHA: `782236125264e6915090650e60737fee0c31beb6`
  - 1,771 خط
  - `#property version=1.083`
  - `EA_VERSION=1.08-C2-H1STRUCT-AUDIT-SB050-T030`
- MultiAudit: `src/Wyckoff_XAUUSD_W0_v1_08_C2_H1STRUCT_MULTI_AUDIT.mq5`
  - Git blob SHA: `b7849fdad9df0cd3e4f0dbc694cd3db92c3040b0`
  - 1,884 خط
  - `#property version=1.084`
  - `EA_VERSION=1.08-C2-H1STRUCT-ML-AUDIT-SB050-T030`

روش: مقایسه ترتیبی خطوط با Longest Common Subsequence (LCS). این روش حفظ یا حذف خطوط موجود را نشان می‌دهد؛ جایگزین parser یا کامپایلر MQL5 نیست.

## 3. محل و ماهیت افزوده‌ها

### 3.1 تابع تشخیصی جدید

تابع `LogStrengthStructureAudit(...)` در حدود خطوط 720 تا 828 افزوده شده است.

برای کندل H1 که معیار قدرت جهت‌دار را پاس کند، موارد زیر را ثبت می‌کند:
- سطح High/Low قبلی برای Lookbackهای 5، 10، 20 و 40.
- عبور یا عدم عبور Close از هر سطح محلی.
- تعداد Pivotهای High/Low تأییدشده.
- سه Pivot اخیرِ قابل استفاده همراه زمان هر Pivot.
- حداقل و حداکثر نوار سه Pivot و پهنای آن برحسب ATR.
- عبور Close از کل نوار سه Pivot.
- فاصله Close تا لبه مرتبط Range برحسب ATR.
- BodyATR، BodyShare و ClosePosition کندل Strength.

این اطلاعات برچسب تشخیصی‌اند؛ خود تابع فقط `LogEvent` را فراخوانی می‌کند و سفارش یا فیلتر ورود ایجاد نمی‌کند.

### 3.2 زمان‌بندی Pivot و کنترل Look-Ahead

آرایه `rates[]` با `ArraySetAsSeries=true` دریافت می‌شود و شروع دریافت در shift=1 است؛ بنابراین:
- `rates[0]` آخرین کندل بسته‌شده H1 است.
- `rates[1]` و `rates[2]` دو کندل بسته‌شده جدیدتر از Pivot فرضی هستند.
- تابع Pivot در indexهای 3 به بعد بررسی می‌کند و مقدار pivot را با دو bar جدیدتر و دو bar قدیمی‌تر مقایسه می‌کند.

پس Pivot فقط پس از وجود دو کندل بسته‌شده جدیدتر قابل تأیید است. در همین منطق، سطح آینده‌نگر یا Pivot تأییدنشده برای تصمیم جاری استفاده نمی‌شود. با این حال، Pivotها هنوز candidateهای ساختار داخلی‌اند و نباید بدون اعتبارسنجی به Creek/Ice قطعی تبدیل شوند.

Lookbackهای 5/10/20/40 نیز از `rates[1..N]` استفاده می‌کنند؛ یعنی کندل فعلی و بسته‌شده از پنجره مقایسه قبلی جدا است.

### 3.3 محل فراخوانی تشخیص

تابع فقط در `ProcessWaitStrength` و پس از عبور کندل از شروط قدرت اولیه فراخوانی می‌شود:
- جهت کندل درست باشد.
- BodyATR حداقل لازم را داشته باشد.
- BodyShare حداقل لازم را داشته باشد.
- ClosePosition حداقل لازم را داشته باشد.

فراخوانی پیش از بعضی ردهای مکانی SOS/SOW قرار دارد؛ بنابراین ممکن است یک کندل قوی که بعداً به علت قرارگیری در سمت نامعتبر Range رد می‌شود نیز رویداد Audit تولید کند. این رفتار برای ممیزی تشخیصی مفید است، اما تعداد این رویدادها را نباید تعداد SOS/SOW تأییدشده یا Candidateهای مستقل معامله تلقی کرد.

### 3.4 افزایش داده دریافتی در حالت انتظار Strength

در `ProcessSignalBar()` تعداد کندل‌های درخواستی فقط وقتی state machine در `ST_WAIT_STRENGTH` قرار دارد افزایش می‌یابد تا Pivotهای تشخیصی قابل محاسبه باشند. این تغییر، داده بیشتری برای مشاهده/ثبت می‌خواند؛ شرط پذیرش SOS/SOW را تغییر نمی‌دهد.

## 4. نتیجه درباره حفظ منطق معاملات

در مقایسه ایستای نسخه‌ها:
- هیچ شرط پذیرش SOS/SOW حذف یا جایگزین نشده است.
- هیچ شرط Spring/UTAD یا Test حذف یا جایگزین نشده است.
- هیچ شرط LPS/LPSY یا M5 breakout/retest/recovery حذف یا جایگزین نشده است.
- هیچ شرط SL/TP، حجم، ریسک، ارسال سفارش یا expiry حذف یا جایگزین نشده است.
- افزوده‌های تشخیصی فقط ثبت چند Lookback/Pivot و افزایش history request در انتظار Strength هستند.

**نتیجه ایستای این بازبینی: PASS برای حفظ خطوط پایه و عدم مشاهده تغییر predicate معاملاتی.**

## 5. محدودیت‌ها و موارد باز

1. **Compile اجرا نشده:** MetaEditor در محیط این بازبینی در دسترس نبود؛ syntax و type resolution با کامپایلر رسمی تأیید نشده است.
2. **Strategy Tester اجرا نشده:** رفتار runtime، تعداد رویدادها و عملکرد معاملاتی نسخه v1.084 هنوز شاهد ندارد.
3. **شناسه داخلی مبهم:** عبارت `ML-AUDIT` در EA_VERSION به MultiLookback Audit اشاره دارد، نه Machine Learning. قبل از هر اجرای جدید باید همین شناسه دقیق در CSV تطبیق داده شود؛ تغییر نام نیز باید در نسخه مستقل و ثبت‌شده باشد.
4. **ثبت زمان:** Event logger قدیمی از `TimeCurrent()` برای ServerTime استفاده می‌کند. جزئیات رویداد barOpen را نشان می‌دهد، اما schema کامل `source_bar_open`، `source_bar_close`، `available_at` و `decision_time` هنوز در CSV جاری پیاده نشده است.
5. **هویت نمونه:** SetupID فعلی Range-level است و شناسه Candidate مستقل نیست. MultiAudit این مشکل را حل نمی‌کند.
6. **Pivot interpretation:** سه Pivot اخیر ممکن است از نظر پهنا بسیار متفاوت و بزرگ باشند؛ این‌ها صرفاً candidate هستند، نه خط قطعی Creek/Ice.
7. **پوشش Audit:** تابع فقط روی کندل‌های قوی اجرا می‌شود؛ همه کندل‌های H1 یا همه فرصت‌های ساختاری را ثبت نمی‌کند.
