# معماری ده‌لایهٔ پروژه Wyckoff W0 / XAUUSD

آخرین بازبینی: 2026-11-04

این معماری مرجع تفکیک مسئولیت‌ها در EA و فرایند پژوهش است. لایه‌های پایین‌تر نباید ضعف لایه‌های بالاتر را با فیلترهای ورود یا تنظیمات ریسک پنهان کنند.

## نمای کلی

| لایه | نام | مسئولیت اصلی | خروجی |
|---:|---|---|---|
| 1 | داده و کیفیت تاریخچه | دریافت M1/tick، ساخت M5/H1/H4، کنترل زمان، OHLC، اسپرد و شکاف‌ها | دادهٔ قابل‌ردیابی |
| 2 | زمینهٔ بالادستی H4 | تعیین زمینه/رژیم و فیلتر اختیاری جهت | Context |
| 3 | تشخیص Trading Range در H1 | RangeHigh/RangeLow، طول، عرض ATR، Touch و عمر Range | محدودهٔ ساختاری اولیه |
| 4 | رویدادهای Wyckoff | تشخیص Spring، UTAD و Test | چرخهٔ رویداد |
| 5 | قدرت و شکست ساختار | SOS/SOW، Internal Swing، Pivot، Range Edge و candidateهای Creek/Ice | طبقه‌بندی Strength |
| 6 | اصلاح و بازآزمایی ساختار | LPS/LPSY، عمق Pullback، نگهداری/ابطال سطح | Setup آمادهٔ ورود |
| 7 | موتور ورود M5 | Breakout → Retest → Recovery/Confirmation → Entry | سیگنال و درخواست سفارش |
| 8 | مدیریت ریسک و سفارش | Position Sizing، SL/TP، RR، Spread، Deviation، محدودیت موقعیت و خطای اجرا | سفارش/معاملهٔ کنترل‌شده |
| 9 | ثبت وقایع و ممیزی | Journal، CSV، شناسهٔ Setup، دلایل رد/انقضا، اتصال رویداد تا Deal | ردپای قابل‌ممیزی |
| 10 | اعتبارسنجی و بهره‌برداری | Compile، Backtest، OOS، Walk-Forward، Forward Demo و دروازهٔ تأیید Live | تصمیم انتشار نسخه |

## زنجیرهٔ ساختاری مورد انتظار

**خرید:** H4 Context → H1 Accumulation/Range → Spring → Test → SOS → LPS → M5 Breakout/Retest/Recovery → BUY.

**فروش:** H4 Context → H1 Distribution/Range → UTAD → Test → SOW → LPSY → M5 Breakout/Retest/Recovery → SELL.

H4 در برخی تنظیمات اختیاری است؛ ساختار H1 و تأیید M5 محور اصلی شاخهٔ Wyckoff W0/C2 هستند.

## سه مسیر موازی پروژه

1. **توسعهٔ استراتژی:** تعریف و پیاده‌سازی قواعد Wyckoff و ماشین حالت ورود.
2. **تحقیق و ممیزی:** Audit ساختار H1، کیفیت Range، Lookback، Pivot و Creek/Ice candidate؛ این مسیر تا تصمیم مستند نباید سیگنال معامله را تغییر دهد.
3. **اعتبارسنجی عملکرد:** کیفیت داده، بک‌تست تکرارپذیر، هزینه/لغزش، آزمون خارج از نمونه و Forward Demo.

## قواعد معماری

- Range envelope، شکست Swing داخلی و ناحیهٔ میانی candidate Creek/Ice سه مفهوم متفاوت‌اند.
- Lookbackهای تشخیصی نباید ناخواسته منطق معاملاتی را تغییر دهند.
- Pivot فقط پس از بسته‌شدن کندل راستِ تأییدکننده قابل استفاده است؛ هیچ دادهٔ آینده‌ای نباید وارد سیگنال گذشته شود.
- هر تغییر راهبردی باید نسخه و آزمایش مستقل داشته باشد.
- ثبت نام Expert و EA_Version در هر گزارش الزامی است.
- «سورس موجود»، «بازبینی ایستا»، «کامپایل»، «تست Tester» و «Forward Demo» وضعیت‌های متفاوت‌اند.

## وضعیت فعلی نسبت به معماری

تا 2026-11-04، مسیرهای Range، Spring/UTAD/Test، SOS/SOW، LPS/LPSY و ورود M5 در چند نسخه پیاده‌سازی و در تست‌های محدود مشاهده شده‌اند. MultiAudit v1.084 در مخزن و از نظر ایستا/تطابق SET بررسی شده، اما کامپایل MetaEditor و اجرای Strategy Tester آن در این وضعیت تأیید نشده است. اعتبار آماری و آمادگی حساب واقعی همچنان اثبات نشده‌اند.
